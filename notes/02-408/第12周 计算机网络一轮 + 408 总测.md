## 周一 · 2027-01-25 · 计网体系结构、性能指标与物理层

`学习` · `2 小时` · 阅读：王道《计算机网络》第 1–2 章

> [!abstract] 今天学什么
> - OSI 七层与 TCP/IP 四层
> - 各层数据单元与典型协议
> - 时延：发送、传播、处理、排队
> - 码元、波特率与比特率
> - 奈奎斯特定理与香农定理
> - 编码与调制、传输介质

> **动手**：
> - 把五层模型与各层典型设备、协议对应起来
> - 区分发送时延与传播时延
> - 用奈氏准则算无噪声信道的最大数据率
> - 用香农公式算有噪声信道容量

### 课后题 1 · 时延 ★★

1MB 数据在 100Mbps 链路上发送，发送时延是多少？若链路长 1000km，传播时延约多少？  
验收：两个数值分开算。

> [!tip]- 提示（先自己卡 3 分钟）
> 发送时延用数据量除以带宽；传播时延用距离除以 2×10⁸ m/s。

> [!success]- 参考答案（做完再对）
> 发送 ≈ 8×10⁶ / 10⁸ = 0.08s；传播 ≈ 10⁶ / 2×10⁸ = 5ms。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · 信道容量 ★★★

带宽 3kHz、信噪比 30dB 的有噪声信道，最大数据率约多少？  
验收：先转信噪比再套香农。

> [!tip]- 提示（先自己卡 3 分钟）
> 30dB → S/N = 1000。

> [!success]- 参考答案（做完再对）
> C = 3000 × log₂(1001) ≈ 3000 × 9.97 ≈ 30kbps。奈氏公式在这里不适用（有噪声）。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] 发送时延 = 数据量 / 带宽
- [ ] 传播时延 = 距离 / 光速
- [ ] 带宽越大发送时延越小，传播时延不变
- [ ] 奈氏：2W log₂V
- [ ] 香农：W log₂(1+S/N)
- [ ] dB 与信噪比的换算

## 周二 · 2027-01-26 · 链路层：差错控制、流量控制与介质访问

`学习` · `2 小时` · 阅读：王道 3.1–3.4

> [!abstract] 今天学什么
> - 奇偶校验、CRC 循环冗余校验
> - 停止-等待、后退 N 帧、选择重传
> - 滑动窗口与序号位数
> - CSMA/CD 与争用期
> - 以太网帧格式与最小帧长
> - MAC 地址与广播

> **动手**：
> - 说明 CRC 的生成多项式与余数关系
> - 比较 GBN 与 SR 的窗口大小限制
> - 由最短帧长反推最大网段长度
> - 说明 CSMA/CD 为什么只用于半双工

### 课后题 1 · 窗口大小 ★★

用 3 位序号的选择重传协议，发送窗口最大是多少？GBN 呢？  
验收：写出两个数值并说明依据。

> [!tip]- 提示（先自己卡 3 分钟）
> 序号空间 2³=8。

> [!success]- 参考答案（做完再对）
> SR：W ≤ 2^(n−1) = 4；GBN：W ≤ 2^n − 1 = 7。超了会导致新旧帧无法区分。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · 最小帧长 ★★

以太网最小帧长 64B，速率 100Mbps，争用期最长多少？  
验收：写出计算。

> [!tip]- 提示（先自己卡 3 分钟）
> 发送 64B 的时间就是争用期上限。

> [!success]- 参考答案（做完再对）
> 64×8 / 10⁸ = 5.12μs，即 2τ ≤ 5.12μs，单程 τ ≤ 2.56μs。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] CRC 用模 2 除法
- [ ] GBN 接收窗口为 1
- [ ] SR 需要逐帧确认与缓存
- [ ] 最小帧长 64B
- [ ] 争用期 2τ
- [ ] 全双工不需要 CSMA/CD

### 课后题 1 · 冲突域 ★

10 台主机接在一台交换机上，冲突域有几个？换成集线器呢？  
验收：分别作答并说明原因。

> [!tip]- 提示（先自己卡 3 分钟）
> 冲突域取决于是否共享同一介质。

> [!success]- 参考答案（做完再对）

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · 子网划分 ★★

192.168.1.0/26 有几个子网可用？每个子网可用主机数多少？  
验收：写出计算。

> [!tip]- 提示（先自己卡 3 分钟）
> 26 位掩码在 C 类里借了 2 位。

> [!success]- 参考答案（做完再对）
> 借 2 位得 4 个子网（.0/.64/.128/.192），每子网 64 个地址，可用主机 62 个（去掉网络地址与广播地址）。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] 集线器不隔离冲突域
- [ ] 交换机每个端口一个冲突域
- [ ] VLAN 隔离广播域
- [ ] 网络地址 = IP AND 掩码
- [ ] /26 每子网 64 个地址、可用 62
- [ ] 片偏移以 8 字节为单位

### 课后题 1 · 最长前缀 ★

路由表有 10.0.0.0/8、10.1.0.0/16、10.1.2.0/24，目的地址 10.1.2.5 匹配哪条？  
验收：说明匹配规则。

> [!tip]- 提示（先自己卡 3 分钟）
> 三条都匹配时取前缀最长的。

> [!success]- 参考答案（做完再对）
> 匹配 /24 那条 10.1.2.0/24。最长前缀匹配保证转发更精确。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · 跨网段 ARP ★★

主机 A 访问另一网段的主机 B，ARP 请求的是谁的 MAC 地址？  
验收：写出目标并说明原因。

> [!tip]- 提示（先自己卡 3 分钟）
> A 无法直接问 B，因为不在同一广播域。

> [!success]- 参考答案（做完再对）
> 请求网关（默认路由器）的 MAC。数据帧先发给网关，再由网关转发。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] RIP 最大 15 跳
- [ ] OSPF 用 Dijkstra、收敛快
- [ ] BGP 用于自治系统之间
- [ ] ARP 只在同一广播域内
- [ ] 跨网段 ARP 找的是网关
- [ ] NAT 修改源 IP 与端口

## 周五 · 2027-01-29 · 传输层：UDP、TCP 连接管理与可靠传输

`学习` · `2 小时` · 阅读：王道 5.1–5.2

> [!abstract] 今天学什么
> - UDP 的特点与适用场景
> - TCP 三次握手与四次挥手
> - TIME_WAIT 与半关闭
> - 序号、确认、超时重传与快速重传
> - 慢开始、拥塞避免、快重传、快恢复
> - 发送窗口 = min(拥塞窗口, 接收窗口)

> **动手**：
> - 画出三次握手与四次挥手的报文与状态
> - 说明为什么握手三次而不是两次
> - 对给定 cwnd 变化图判断处于哪个阶段
> - 算超时后的 ssthresh 与 cwnd

### 课后题 1 · 三次握手 ★★★

为什么 TCP 建立连接需要三次握手，两次不行吗？  
验收：给出核心原因。

> [!tip]- 提示（先自己卡 3 分钟）
> 两次无法让双方都确认「对方能收也能发」。

> [!success]- 参考答案（做完再对）
> 第三次握手让服务端确认客户端已收到自己的 SYN，且客户端确实能接收；同时防止历史失效连接请求造成资源浪费。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · 拥塞窗口 ★★

cwnd=16 时发生超时，ssthresh 与新的 cwnd 各是多少？  
验收：写出规则与数值。

> [!tip]- 提示（先自己卡 3 分钟）
> 超时视为严重拥塞。

> [!success]- 参考答案（做完再对）
> ssthresh = 16/2 = 8，cwnd 重置为 1，重新慢开始，涨到 8 后转拥塞避免。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] SYN、ACK、FIN 标志位
- [ ] TIME_WAIT 等 2MSL
- [ ] 两次握手无法确认客户端接收能力
- [ ] 超时：ssthresh=cwnd/2，cwnd=1
- [ ] 快重传：cwnd 减半后进入快恢复
- [ ] 接收窗口由接收方通告

> - 比较 POP3 与 IMAP 的差异

### 课后题 1 · DNS 查询 ★★

本地域名服务器向根域名服务器查询时，通常用递归还是迭代？  
验收：说明理由。

> [!tip]- 提示（先自己卡 3 分钟）
> 根服务器不替你跑完全程，只指路。

> [!success]- 参考答案（做完再对）
> 迭代查询。根只返回下一级服务器的地址，由本地服务器继续问；递归则由被请求方代为完成，负担大，根通常不这么做。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

### 课后题 2 · FTP 端口 ★

FTP 的控制连接与数据连接分别用什么端口？哪个先建立？  
验收：写出端口与顺序。

> [!tip]- 提示（先自己卡 3 分钟）
> 控制连接贯穿整个会话。

> [!success]- 参考答案（做完再对）
> 控制连接 21 端口先建立并保持；数据连接 20 端口（主动模式）在每次传输时临时建立，传完即关。

- 状态：`未做` → 做完改成 `已独立完成` / `看答案`

**完成标准**

- [ ] DNS 先查本地缓存
- [ ] HTTP/1.1 默认 keep-alive
- [ ] HTTPS = HTTP + TLS
- [ ] SMTP 只发不收
- [ ] FTP 控制连接 21、数据连接 20
- [ ] 封装自上而下、解封装自下而上
